# HerBiz: Compliance Agent - QA review of source monitoring and discovery (WS-C)

**Business line:** HerBiz (HomepreunerHub) - Compliance Agent prototype. Not legal or tax advice.
**Reviewer:** independent QA (monitoring reliability and discovery), 17 Oct 2026. **Mode:** read-only for the repo; no network.
**Scope:** `compliance_agent/rag_c/monitor.py`, `discovery.py`, `rag_c/__main__.py` (monitor / discover), `tests/test_ws_c_monitoring.py`, launchd template.
**Evidence:** every finding below was observed with my own scripts in `scratchpad/qa/monitor/` (exp1.py ... exp5.py), using synthetic PDFs (PyMuPDF), fake fetchers, mocked `urlopen` and copies of the locked raw files. Existing suite: 11/11 pass (observed 17 Oct 2026).
**Note:** `rag_c/__main__.py` shows as modified in the working tree (another session may be editing it). I reviewed the current file.

## Verified working (no finding)

- LocalFetcher refuses without `allow_network=True`; CLI needs exactly one fetcher flag. Redirect to a non-official host, `http://` and off-allowlist hosts are refused and become `fetch_error` (no crash).
- A CLI monitor run (fixtures, explicit `--state` / `--report-dir` in scratch, real register and DB) changed **zero files** in the repository (mtime/size snapshot before and after). The DB is opened `mode=ro`.
- The state is written atomically (tmp + replace). Sequential same-day runs never overwrite a report (`_run2`).
- Whitespace-only changes, and a page break moved inside an article, are classed as cosmetic or same. A number changed deep inside a long article (split into parts over 3,000 chars) is still found, because parts are merged per article. A front-matter date change is found (medium). Renumbering 14 to 16 shows as removed + added (high, in scope). A switch from PDF to Firecrawl markdown of the same text only gives `changed_cosmetic` (low).
- 403/500 give `fetch_error` and keep the old baseline. Recovery after errors returns `same`.

## Findings

| id | severity | finding | reproduction | suggested fix |
|---|---|---|---|---|
| MON-01 | High | **One bad item aborts the whole run.** Exceptions are not caught per URL. A corrupt or truncated PDF (`CollectError` from pdftotext), `ssl.SSLError`, `http.client.IncompleteRead`, or any fetcher exception (e.g. `TimeoutError` from a custom fetcher) ends the run with no state, no report and no alerts. When unattended, one broken FTA file blinds the monitor every day, and the only trace is stderr. | exp1.py "corrupt pdf day2" -> CRASH CollectError; exp2.py: SSLError, IncompleteRead, fetcher TimeoutError -> CRASH | Wrap fetch + extract per item in `try/except Exception`, and emit a `fetch_error` / `extraction_error` alert with the exception text. In `http_fetch`, also catch `ssl.SSLError`, `http.client.HTTPException` and `OSError`. |
| MON-02 | High | **The state is advanced before the report is written.** `write_outputs` replaces the state first. If the report or alerts write fails (permissions, disk full, crash), the next run compares against the new state and stays quiet, so the change alert is lost for good. There is no other record (alerts exist only in that run's files). | exp4.py: report dir chmod 500 -> PermissionError, `state written anyway: True` | Write the report and alerts first (exclusive create), then the state last. Or keep the "unacknowledged alerts" inside the state and re-emit them until a person acknowledges them. |
| MON-03 | High | **A source that is already gone at the baseline run is silent.** A 404/410 with no previous state records `removed` with **no alert**. 19 of 26 watched URLs were "removed" on the first run with `high_alerts: 0`. If the first live run happens after a URL has gone (likely for the superseded 2024/2025 ER files), nobody is told. | exp2.py "first run 404 (baseline)": `['removed'] []`; exp4.py run1: `removed 19`, high_alerts 0 | On the first observation, alert `removed` (or `not_found_at_baseline`, high for registered versions and medium for candidates). |
| MON-04 | High | **A templated line is erased before comparison, which causes false negatives.** `strip_running_headers` drops every line that repeats on 60% or more of pages (4+ pages) once digits are replaced by `#`. A line like "The penalty ... shall be AED 3000." that recurs per page with different numbers is deleted, so changing AED 3000 to 9000 gives `same`. This fits penalty schedules (Cabinet Decision 40 tables), which are in the watch list. | exp1c.py "FN number change in a line templated across pages": status=same | In the monitor, compare with header stripping limited to the top and bottom 2 lines of each page. | MON-06 | Medium | **"Page X of N" / print-date footers on short PDFs (<4 pages) make every unit substantive.** Header stripping needs 4+ pages, so footers stay in the text. | MON-07 | Medium | **HTML pages are compared by position ("Paragraph N").** Inserting one banner paragraph shifts every key, so 6 paragraphs show as substantive. Also, the in-scope list of FTA-VAT-REG-PAGE ("Paragraphs 1-9") is filtered out, so a real threshold change on the registration page can only ever be **medium**, never high. | exp5.py "HTML page, one banner paragraph inserted": added 1, substantive 6; watchlist REG-PAGE in_scope `[[]]` | Key HTML units by a hash of normalized text (set comparison), with an anchor phrase / content region (`must_contain`). Map paragraph scope to anchor phrases, or treat any substantive change on a registered page as high. |
| MON-08 | Medium | **Empty or failed extraction is reported as "all articles removed" (substantive change), not as an extraction failure.** An image-only PDF, a soft-404 HTML page with HTTP 200, or an empty body gives `changed_substantive_in_scope` (high), and the empty state becomes the baseline. When the real file returns, every article shows as "added": a second false high. | exp1.py "image-only pdf day2", "soft 404 html with 200"; exp2.py "empty 200 body" | If units are 0 (or under 20% of the previous count), or the content type is not what was expected (PDF URL served as HTML), raise `extraction_suspect` and **do not** replace the baseline. |
| MON-09 | Medium | **A listing whose first run failed never proposes the documents already on it.** After a `fetch_error`, `prev` exists without `links`. ## Scheduling readiness (unattended daily run)

**Gate: Blocked** for unattended scheduling. It is fine for supervised, manual runs.

What would break if the launchd template were installed today:

1. **Silent total failure:** any one bad file or network error class (MON-01), or a corrupt state (MON-15), stops every daily run. The only evidence is `launchd.err.log`. There is no heartbeat or "last successful run" check, and the exit code is 0 even with high alerts, so nothing tells the founder.
2. **Lost alerts:** a failed report write after the state update (MON-02), or a concurrent manual run (MON-16), loses changes permanently.
3. **Nobody is notified:** alerts are only written to files in a git-ignored folder. A daily file nobody opens equals no monitoring. A notification step (draft only, approval-gated) or a weekly summary in the board pre-read is needed.
4. **launchd specifics:** `StandardOutPath` / `StandardErrorPath` point into `data/monitor/`, which does not exist until the first successful run. If launchd cannot open the log path, the job can fail with no visible output. `/bin/zsh -lc python3` depends on login-shell PATH and on pypdf/certifi being in that interpreter. The working directory is a git **worktree** (`..._ws_c`) that can be cleaned up or moved. The Mac must be awake (runs coalesce on wake, so a missed day is not flagged).
5. **Noise will train people to ignore it:** daily medium `fetch_error` for WAF-blocked pages with no escalation (MON-17), nav-link churn (MON-11), footnote renumbering and short-PDF footers (MON-05/06), and HTML paragraph shifts (MON-07).
6. **Baseline blind spots:** URLs already gone at the first live run raise no alert (MON-03). The first live run should be a supervised baseline whose report a person reviews.

**Minimum before scheduling:** fix MON-01, 02, 03, 15 and 16. Add a nonzero exit code or a "high alerts" marker file, plus a heartbeat check. Create `data/monitor/` up front. Use an absolute interpreter path. Run supervised for 1-2 weeks to measure noise.
