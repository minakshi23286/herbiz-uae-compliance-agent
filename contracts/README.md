## Rules applied (doc 16 §0.1)
- **Additive by default.** Every object is closed (`additionalProperties: false`), so a new field needs a minor version that WS A publishes, on the semantics owner's written request. Major versions need WS A sign-off and a founder note.
- **Fail closed.** A payload that does not validate is shown as "unavailable", and its audit record carries `error`.
- **T2-D2.** `audit_record.request.query_text` may be non-null only when `gate.action` is `allow`; the profile must be synthetic (`synthetic: true` is required). A blocked answer has `retrieval: null` and `query_text: null`.
- **T2-D3.** `confidence = {level: low|medium|high, basis: [codes], numeric: null}`; any numeric value is invalid.
- **No approval anywhere.** `release_approved` is always `false`. `review_status` never takes the value `approved`. Conflicts always have `precedence_known: false` and `resolution: "escalate"`.
- **No official text in audit records.** `retrieval.items[]` in an audit record has no `text` field. Only the internal `retrieval_result` payload may carry `text`.
- **Timestamps** in audit records use Asia/Dubai (`+04:00`). The first record of a chain has `prev_record_sha256` = 64 zeros.
