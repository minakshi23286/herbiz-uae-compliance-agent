# HerBiz: Compliance Agent — QA2 adversarial review: lifecycle test, contract v1.1, DB protection

**Business line:** HomepreunerHub / HerBiz (Agent championship) · **Date:** 17 Oct 2026 · **Branch / HEAD:** `ws-c-source-intelligence` / `ef687b0` · **Reviewer:** independent QA2 (read-only) · **Not legal or tax advice.**

**Scope and safety.** No project file was edited. All experiments ran on copies in `scratchpad/qa2/` (`base/` = rsync copy of the worktree without the two protected DBs; `mut/` = mutants; `inst/` = instrumented test copy; `hard/` = suite with triggers on every Store; `prot/` = OS-level and trigger experiments). The authoritative `CL_compliance_agent_app/data/CL_compliance.sqlite3` was only md5-read and opened `?mode=ro`: md5 `26e202b87a062288e56bcda1de9b0217` before and after; mode 0644, no flags, `journal_mode=delete`, no side files. No network.

Evidence files: `mutate.py` (mutation harness), `interface_edge.txt`, `prot/triggers.txt`, `prot/os_exp.txt`.

## Manual-by-design boundary
- **Collection (founder-approved), reviewer approval (`review_source`, a named qualified reviewer) and the register update:** these are manual, and that is right. It fits the approval rule, and no automated job should activate anything. The monitor and `add_proposals` changed nothing, and the test proves that well.
- **What is wrong is that the two manual steps are not tied together.**
  - "Activation" is a free-form JSON edit that nothing checks against the DB review.
  - The DB review in turn has no effect on certification.
- **Fix:** keep both steps human, but make `validate()` refuse a register approval that has no matching DB approval and audit event (Q-C5). Optionally provide a founder-run `activate` helper that writes the register entry from the DB record.
